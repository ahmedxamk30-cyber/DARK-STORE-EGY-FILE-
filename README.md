# DARK STORE

متجر رقمي بالعربية (RTL) لشحن الألعاب وخدمات التواصل الاجتماعي، مبني بـ Next.js وTypeScript وSupabase.

## المتطلبات

- Node.js 20 أو أحدث
- حساب Supabase ومشروع جديد

## التثبيت

```bash
npm install
cp .env.example .env.local
npm run dev
```

## متغيرات البيئة

| المتغير | عام؟ | الوصف |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | نعم | رابط مشروع Supabase |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | نعم | المفتاح العام (anon) |
| `NEXT_PUBLIC_SITE_URL` | نعم | رابط الموقع النهائي |
| `SUPABASE_SERVICE_ROLE_KEY` | **لا، سري** | لا يُستخدم في الواجهة أبدًا |

لا تضع مفتاح `service_role` أو أي مفتاح مزود خدمة داخل ملفات الواجهة، ولا تضعه في متغير يبدأ بـ `NEXT_PUBLIC_`.

## إعداد قاعدة البيانات

**استخدم قاعدة بيانات Supabase جديدة لهذا المخطط.** لا تنفّذ `schema.sql` على قاعدة موجودة عليها بيانات أو جداول من إصدار مختلف قبل أخذ نسخة احتياطية ومراجعة توافق الأعمدة والأدوار.

1. افتح Supabase > SQL Editor.
2. نفّذ محتوى `supabase/schema.sql` كاملًا.
3. نفّذ `supabase/migrations/0002_phase2.sql`.
4. نفّذ `supabase/migrations/0003_security_hardening.sql`.
5. أنشئ حسابك من صفحة التسجيل.
6. لترقية حسابك إلى مالك، نفّذ في SQL Editor:

```sql
update public.profiles set role = 'super_admin' where id = '<your-user-uuid>';
```

الصلاحيات:
- `super_admin`: كل شيء، بما في ذلك تعيين الأدوار.
- `admin`: إدارة المحتوى والمنتجات والطلبات والإيداعات والأرصدة.
- `support`: عرض الطلبات والإيداعات والمستخدمين.
- `user`: الشراء وإضافة الرصيد فقط.

الأمان الحقيقي موجود في قاعدة البيانات عبر RLS والدوال المحمية، وليس فقط في الواجهة.

## النشر

المشروع متوافق مع أي استضافة تدعم Next.js (مثل Vercel أو Cloudflare عبر OpenNext).

1. ارفع المشروع إلى مستودع Git.
2. اربطه بالاستضافة، وأضف متغيرات البيئة أعلاه في إعدادات المشروع.
3. اربط الدومين المخصص من إعدادات الاستضافة، ثم حدّث `NEXT_PUBLIC_SITE_URL`.
4. في Supabase > Authentication > URL Configuration، أضف رابط الموقع النهائي إلى Site URL و Redirect URLs.

## الفحص قبل النشر

```bash
npm run typecheck
npm run build
```

## ما الذي يعمل

- الصفحات: الرئيسية، الألعاب، السوشيال ميديا، العروض، المنتجات، طلباتي، المحفظة، إضافة الرصيد، حسابي، تسجيل الدخول، إنشاء حساب، تواصل مع المطور.
- المصادقة: تسجيل دخول وإنشاء حساب وتسجيل خروج عبر Supabase Auth. المسارات المحمية تُفحص في الوسيط (middleware).
- الشراء: يرسل المتصفح معرّف المنتج ومعرّف اللاعب فقط. السعر والرصيد يُتحققان داخل دالة `place_order` في قاعدة البيانات، وتُخصم المبالغ بشكل ذري.
- الإيداع: يرفع المستخدم صورة الإثبات إلى مجلد خاص به، ويُنشأ طلب بحالة "بانتظار المراجعة". **لا يُضاف الرصيد إلا بعد اعتماد أحد المسؤولين** عبر `review_deposit`.
- فودافون كاش والتحويل البنكي: لا يوجد تكامل دفع آلي. المستخدم يحوّل يدويًا ويرفع الإثبات، والمراجعة يدوية.
- DARK CONTROL على المسار `/dark-control`:
  - المستخدم العادي يحصل على 404.
  - الدعم: عرض الطلبات والإيداعات والمستخدمين.
  - الإدارة: الأقسام والمنتجات والأسعار والعروض، محرر الصفحة الرئيسية، اعتماد الإيداعات، تعديل الأرصدة، الإعدادات.
  - المالك: تغيير أدوار المستخدمين.
- محرر الصفحة الرئيسية: إضافة الأقسام وحذفها وإخفاؤها وتحريكها لأعلى ولأسفل، مع معاينة فورية لكل قسم قبل الحفظ.

## ما لم يُنفذ بعد

- السحب والتحريك بالسحب والإفلات في محرر الصفحة الرئيسية، والترتيب الحالي بالأزرار.
- مسودة ونشر منفصلان: التغييرات تظهر للزوار مباشرة بعد الحفظ.
- رفع الصور من الجهاز: الصور تُدخل كروابط https فقط.
- بريد المستخدمين في لوحة التحكم غير معروض، لأن البريد محفوظ في Supabase Auth ولا يُنسخ إلى جدول الملفات.
- اختبارات تلقائية.
